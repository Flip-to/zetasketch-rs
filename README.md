# zetasketch-rs

A byte-compatible Rust port of [Google ZetaSketch](https://github.com/google/zetasketch)
HyperLogLog++, the sketch format that BigQuery `HLL_COUNT.*` produces and consumes.

- Decodes `AggregatorStateProto` sketches, both sparse and dense.
- Merges them the way the reference does: max over **decoded** registers, never a bytewise max
  over serialized bytes. Sparse sketches are promoted to dense, and precision is lowered when
  the operands differ.
- `estimate()` returns what `HLL_COUNT.EXTRACT` / `HLL_COUNT.MERGE` return. It includes the
  bias-correction tables and the switch to linear counting at low cardinalities.
- `serialize()` returns what `HLL_COUNT.MERGE_PARTIAL` returns, byte for byte.
- `add_long` / `add_int` / `add_str` / `add_bytes` hash values with `Fingerprint2011`, the same
  hash as the reference and BigQuery.
- No dependencies and `#![forbid(unsafe_code)]`.

```rust
use zetasketch::HyperLogLogPlusPlus;

// Bytes from BigQuery: SELECT HLL_COUNT.INIT(user_id) ...
let mut acc = HyperLogLogPlusPlus::from_bytes(&sketch_a)?;
acc.merge_bytes(&sketch_b)?;                 // HLL_COUNT.MERGE_PARTIAL semantics
let distinct = acc.estimate();               // == HLL_COUNT.EXTRACT
let bytes = acc.serialize();                 // == HLL_COUNT.MERGE_PARTIAL bytes
```

## Parity evidence

| Suite | What it checks | Source |
|---|---|---|
| `tests/golden_corpus.rs` | 84 sketches: decode, estimate, re-serialize. 5 merges. 98 sketches built from `0..n` as `i64` (hash and build path). Precisions 4 to 20 | Java ZetaSketch HEAD `d098c49`, through the [zetasketch-cpp](https://github.com/rowkeydb-com/zetasketch-cpp) golden corpus (Apache-2.0) |
| `tests/bigquery_golden.rs` | 66 `HLL_COUNT.INIT` sketches (INT64, STRING, BYTES; p = 10 and 15; n = 1 to 10^6): decode, `EXTRACT`, bytes. Each sketch is rebuilt from the same values. 13 merges: sparse+sparse, the sparse→dense crossover, sparse+dense, dense+dense, precision lowering, 10-way, duplicates. Each checks `MERGE_PARTIAL` bytes and the `MERGE` estimate | BigQuery, generated by `scripts/gen_bigquery_fixtures.py` from `GENERATE_ARRAY` inputs only |

All fixtures are synthetic. No real data is committed or needed.

## Development

```bash
cargo test --release
cargo clippy --all-targets -- -D warnings
uv run scripts/check_docs_layout.py
```

The other scripts regenerate the generated inputs:

- `scripts/gen_bias_data.py <Data.java>` rebuilds `src/bias_data.rs` from the reference tables.
- `scripts/gen_bigquery_fixtures.py --project <p>` re-queries BigQuery for the fixtures.

Design and decisions live in [`docs/`](docs/README.md). Contributor and agent rules are in
[`CLAUDE.md`](CLAUDE.md) and [`AGENTS.md`](AGENTS.md).
